# Setting-up-Active-Directory-for-Identity-and-Access-Management

# Introduction
This project focuses on setting up and configuring Active Directory (AD) and Identity and Access Management (IAM) within a Windows Server environment integrated with a Windows 8 client machine. The goal was to create a functional directory service environment to manage users, computers, and permissions efficiently. Active Directory serves as the backbone of centralized authentication, enabling secure access control and identity management within a networked setup. By using virtualization tools, I was able to simulate a real enterprise environment where domain controllers, users, and policies could be managed remotely. This project also provided a deeper understanding of how AD and IAM support organizational security and workflow automation.

# Objectives
The objectives of this project were to:
1. Install and configure Active Directory Domain Services (AD DS) on Windows Server.
2. Create and manage organizational units (OUs), users, and groups for centralized control.
3. Implement IAM policies to define roles, permissions, and access levels.
4. Connect a Windows 8 client machine to the domain to test user authentication and policy enforcement.
5. Explore Group Policy Objects (GPOs) for enforcing security and system configurations.
6. Understand the relationship between directory services and enterprise identity management.

# Benefits
This project provided valuable hands-on experience in setting up enterprise-level access management. It demonstrated how Active Directory simplifies user and resource management through centralized control. IAM integration enhanced understanding of role-based access control (RBAC), ensuring users only have access to the resources they need. Working in a virtual environment made it possible to test different configurations and policies safely. The setup also improved familiarity with Windows Server tools, DNS management, and user authentication processes. Ultimately, this project bridged the gap between theory and practice, building real-world readiness for system and network administration roles.

# Challenges
During the setup process, one major challenge encountered was the failure to link the IP address between Windows Server and the Windows 8 client machine. Despite proper configuration of network adapters and DNS settings, the client system was unable to connect to the domain. After several troubleshooting attempts, the issue was resolved by uninstalling and reinstalling the network adapter on the Windows 8 system and reconfiguring its IP settings. Other challenges included ensuring proper DNS configuration, synchronizing time between both systems, and managing user permissions without conflicts. Each obstacle provided valuable troubleshooting experience that strengthened problem-solving and diagnostic skills.

# Conclusion
Completing this project helped with the following
1. Deepened my understanding of enterprise directory management and access control systems.
2. It reinforced how essential Active Directory and IAM are for maintaining security, consistency, and organization across networked systems.
3. Overcoming the IP linking issue highlighted the importance of patience and methodical troubleshooting in real-world IT environments.
4. This experience also showed how virtualization and lab setups can simulate real corporate infrastructures effectively.

In conclusion, building and configuring Active Directory and IAM on Windows Server and Windows 8 was not only a technical exercise but a meaningful step toward mastering system administration and network identity management.
